# node 変換の field で text だけの group の capture（#89）

#86 の調査中に手で見つけた差（修正前から存在）。`P ::= 'i' | 'j'`（写像なし・text だけ）、
`Root ::= '[' ( P P ) @x Leaf @x ']'` で入力 `[ijx]` に対し `x`: java=`["ij", Leaf]`、rust=`["i", "j", Leaf]`。
**Rust が逸脱**で、Rust だけを直した。新しい D 行は足していない（D-032 で決まっている）。

## 1. 契約の読み

- D-032: cardinality は「一度の成功解析で共存し得る値の個数」。capture site の量指定子は出現回数としてそのまま数え、
  site より内側の量指定子は意味値だけを増やす。**text だけの領域は一致範囲全体で 1 つの値**。
- `( P P )` の意味形は None（`P` は写像なしの text だけの規則、#86 と同じ判定）。したがって `( P P ) @x` の 1 出現は
  一致範囲 `ij` の字句 1 つ。`x` が同じ規則に `Leaf @x` の site を持ち node 変換になっても、出現の値の作り方は変わらない。
- 出現が 2 つ（`P @x P @x`）なら値も 2 つ（`["i", "j"]`）。反復の capture（`( P P )* @x`）は要素ごとの出現で、要素ごとに字句 1 つ。
- 旧実装: `unlaxer-parser/docs/nested-capture-migration.md` の表の `('a' @value 'b') @value` → `["a", "ab"]`（group の出現は一致範囲の
  字句 1 つ）。Java 生成 runtime も、plain text（`values == null`）の capture は `Value(start, end)` 1 つにする（`Session.capture`）。
- D-078（意味値を持つ選択の text 候補は字句 1 つ）・#86（意味値の領域の中の text 規則は区切り）とは独立で、どちらの形も変えない。

## 2. 原因

Rust の mapping は field の変換で経路が分かれる。`( P P ) @x` だけなら text 変換（`text_values`）で出現ごとに
`semantic_text` を 1 つ作るので差は出ない。`Leaf @x` があると node 変換（`node_values`）になり、出現ごとに capture の子を
`build_values_into` で組み立てる。`( P P )` は意味形 None なので `Values` で包まれず、写像なし規則 `P` の `Event::Rule`
がそれぞれ（値の領域の外なので #86 の抑止も効かず）一致範囲の字句を 1 つずつ足していた。

## 3. 修正（Rust のみ）

- 生成器（`crates/ubnfc-rust/src/mapping.rs`）: node 変換の field について、site の 1 出現の式（Optional / Repeat に付いた site は
  要素の式）の意味形が None の site を `text_sites` として静的に数え（`text_only_site`）、`node_values` に渡す。
- 生成 runtime（`templates/runtime.rs` の `node_values`）: `text_sites` の出現は、空でなく recovery を含まなければ
  `semantic_text(child, span)` 1 つを値にする（leaf fallback の昇格は従来どおり）。それ以外は従来の組み立て。
  空の一致・recovery を含む出現の扱いは変えていない。
- Java は変えていない。
- 生成物: P4 Rust（`examples/p4-rust/src/generated/runtime.rs`）と self-host（`crates/ubnfc-selfhost/src/generated/runtime.rs`）を
  再生成。差分は `node_values` の呼出しに引数 `&[]` が増えたことと runtime 本体だけで、**両文法とも `text_sites` が空**
  （P4: 140 呼出し、self-host: 19 呼出し）なので振る舞いは不変。canonical AST golden は不変。

## 4. 回帰試験

- `crates/ubnfc-fuzz/tests/text_group_capture_value.rs`（新規）: 両 backend の突き合わせ + 値の固定。
  `( P P ) @x Leaf @x`（issue の形）、`( P P ) @x`、`P @x P @x`（2 出現 → 2 値）、`P @x P @x Leaf @x`、
  `( P P )* @x Leaf @x`（要素ごと）、`( P P )? @x Leaf @x`（不在は値なし）、D-078 の形 `( P P | Leaf ) @x '-' Leaf @x`、
  #86 の形 `( P Leaf ) @x '-' Leaf @x`。修正前の Rust では issue の形で落ちることを確かめた。
- 所見 `crates/ubnfc-fuzz/findings/diff-ast-fields-x-issue89/`（手で縮めた形。seed なしなので `finding.json` は無い）。
- **固定 seed campaign（`tests/campaign.rs`）には足していない**: 下の掃き出しでこの形を出す seed が 4 帯のどこにも無く、
  campaign は seed で文法を作るため、固定できる seed が存在しない。回帰は上の targeted 試験が担う。

## 5. 掃き出し

各帯 201 seed × 12 入力、`--jobs 4 --shrink-builds 0`。修正前（B = `origin/master` 7dbcdec の生成器）と修正後（F）を、
同じ fuzz バイナリで `UBNFC_RUST_GENERATOR` だけ差し替えて比べた（Java 側は同一）。

| 帯 | 比較 / 全受理（B = F） | 消えた signature | 代表 seed の変化 | 増えた signature |
|---|---|---|---|---|
| 標準 v1（1–） | 2412 / 646 | なし | なし | なし |
| 標準 v2（100001–） | 2412 / 467 | なし | `diff:/diagnostics/*/farthestExpected/*`（`KNOWN`）の代表 100013 → 100014 | なし |
| 直接 capture v1（1000000–） | 2412 / 513 | なし | なし | なし |
| 直接 capture v2（1100000–） | 2412 / 246 | なし | なし | なし |

- v2 の代表 seed の移動は並列実行での記録順の揺れ: seed 100013 を `--jobs 1` で単独再実行すると B・F とも同じ
  `diff:/diagnostics/*/farthestExpected/*` を出す。
- discard・driver error はどの帯も 0。消えた signature が無いのは、fuzzer がこの形（node 変換の field に、写像なし text 規則を
  2 つ以上含む group の capture）を生成していないため。
