# LL(1) 認識表の Rust 実装と A/B（issue #2）

JSON 1 MB の認識は **off 0.014623 → on 0.012878 µs/byte（中央値、11.9% 改善）**。
目標の ≤0.015 µs/byte を満たす。P4 の静的被覆は **386/1,043 式（37.0%）**、
規則本体では **5/124（4.0%）**。今回の Rust 実行は文法全体の scope / recovery を除くため、
P4 の**実行被覆は 0% で、効果はない**。計時の揺れを改善として数えない。
Java は受け入れ条件付きの [#39](https://github.com/opaopa6969/ubnfc/issues/39) に分けた。

## 変更と判定の範囲

D-091、[設計文書](../design/09-ll1-tables.md)。front は Choice の非 nullable 候補の FIRST 上界が
互いに素であることを確かめ、閉領域の状態表を additive な `plan.ll1` に出す。
Rust は明示 stack で列・選択・Call・Optional・Repeat を進める。
選択候補の試行を確定する LL(1) 性だけを利用し、Optional / Repeat の PEG の巻戻しは維持する。

この段階では診断・AST・arena AST・出現表・lexical を要求しない認識だけが対象で、
scope / recovery を持つ文法と、memo 対象を含む根を実行しない。
既定は `ParseOptions::ll1 = true`、false は参照経路。表の不一致や上限到達では Session を変更せず
既存評価へ戻る。診断と AST の経路は従来のまま。`statistics` の機構計数は最適化に従って変わる。

D-072 の走査関数を表の辺として再利用する。文字列・数値・空白の文字単位ループを再導入せず、
外側の規則呼出し、式 wrapper、transaction の回数を減らす。JSON 1 MB の通常の規則本体評価は
**208,727 → 1**、memo hit / entry は両側とも 0。表内の Call はこの計数には含めないので、
これは「文法上の規則を 1 個しか読まない」という意味ではない。

## 計測条件

2026-11-01 JST。ベースは `763eb5c` と本変更。A/B は別 binary の比較ではなく、
**同じ生成 parser・同じ binary の `ll1` だけを切り替える**。
scan / predict / factor / buffer reuse は既定のまま。認識のみ、EOF 必須。

## JSON

JSONTestSuite `1ef36fa01286573e846ac449e8683f8833c5b26a` の y_* から、既存の
`benchmarks/scripts/make-json-inputs.py` で作った入力を使用する。IR の全 **120/120 式、16/16 規則本体**が
静的な対象で、成功時は入口から全域を表で認識できる。

| 入力 | byte | off µs/byte | on µs/byte | 変化 |
|---|---:|---:|---:|---:|
| 1 KB | 1,067 | 0.012602 | 0.011040 | −12.4% |
| 10 KB | 10,066 | 0.015658 | 0.014144 | −9.7% |
| 100 KB | 100,039 | 0.013335 | 0.011666 | −12.5% |
| 1 MB | 1,000,112 | 0.014623 | **0.012878** | **−11.9%** |

1 MB の各周の on 中央値は 0.014780 / 0.012421 µs/byte。
共有機での揺れは残るが、両周とも 0.015 以下で、全サイズの 18 サンプル中央値も目標以下。
今回 ANTLR を再計測した比較ではなく、issue が定めた絶対目標に対する評価である。

## P4 の被覆と効果

計測対象は master が backend の回帰・計測用に固定した `ir/frozen/tinyexpression-p4-f86ce8a5.ir.json`
（元の tinyexpression `f86ce8a5ab0ab7d23fdba2cd477187df8aa7607c`）。
静的な対象式は 386/1,043（37.0%）。対象の規則本体は `NumberReturnType`、`AddOp`、
`MulOp`、`EqualityOp`、`TypeKeyword` の 5/124（4.0%）。
不適格な親に接する単発の終端も静的被覆に含むため、これを実行被覆と同一視しない。

PR #40 の pin 更新も取り込んだ。最新 pin `c736c2c66e4569ebc5e22f1f0c5125a045679d35` の P4 golden では
静的被覆は **388/1,089 式（35.6%）、5/130 規則本体（3.8%）**。文法の変化と backend の効果を分けるため、
計時と生成物の回帰は master と同じ固定 IR を使う。どちらの P4 文法も実行被覆は 0% である。

P4 は scope 効果を持つ。親が子孫の事象を読む場合の局所的な証明まで追加すると
今回の変更範囲が広がるので、Rust は表を実行しない。生成 parser に `self.options.ll1` の
入口が存在しないこともテストで固定した。この保守的な制約が今回 P4 に効果がない理由である。

| 入力 | byte | off ms | on ms |
|---|---:|---:|---:|
| complex | 332 | 0.069691 | 0.074537 |
| complex-x64 | 20,923 | 6.340568 | 6.003975 |

同じ経路の比較で差の符号も揃わず、**表駆動の効果は 0**。この数値差を速度改善・退行と解釈しない。
P4 に効かせる次の手は、scope が読む capture と token extent を局所的に証明し、
必要な事象だけを再生することである。memo・左再帰の塔は引き続き通常経路に残す必要がある。

## 同値・退行の検証

- 生成 Rust の LL(1) テスト 5 件。JSON 全域・再帰の判定、重なる FIRST / nullable / lookahead の除外、
  改変表の無効化と並べ替えた表の受理、P4 scope の実行抑止を検査する。生成 parser を実行し、成功・失敗・部分入力・Unicode・
  深さ 0/1/2/4/32/100 と仮想 stack 上限超過、scan on/off、AST・arena AST・出現表・診断の各 mode を比較。
  小さい記号集合の長さ 4 の全文字列 625 件と、JSON の切断位置も比較する。生成物の clippy も実行。
- JSONTestSuite の UTF-8 **293 件（受理 116 / 拒否 177）**は on/off の全 ParseResult が機構計数を除き一致。
  不正 UTF-8 25 件は `&str` API の対象外。新しい受理・拒否はない。
- 差分 fuzz campaign に Rust の LL(1) on/off を追加。既存の scan on/off は両側で LL(1) を外し、独立性を保つ。
  固定 campaign 8 テストが成功し、LL(1) の新規差分は 0。
- 既存 IR golden **27 件（固定 P4 IR を含む）**は追加の `plan.ll1` をテキストから除くと **byte 一致**。
  semantics、analysis、requiredFeatures、既存の plan キーも変更しない。schema の全型検査も成功。
- front / Rust / fuzz の library clippy は `-D warnings` で成功。
- 既存の左再帰テスト 3 件と生成 golden テスト 3 件も成功。式 ID で部分表を照合し、
  意味論の加工後に古い表が残った IR は表を生成・実行せず参照経路を使う。既存の IR の受入れと
  左再帰診断を優先する。検証器の変更前後で JSON の生成ソースは全ファイル byte 一致する。
- Java jar を `mvn -q -DskipTests package` で作成後、指定 pin の fixture で
  `cargo test --workspace --no-fail-fast` を実行。worktree の隣接 fixture を環境変数なしで探す CLI テストは
  配置不足で失敗したが、同じ commit を専用一時ディレクトリへ展開し CI と同じ隣接 fixture 配置にすると
  2 件とも成功する。共有の隣接ディレクトリには手を加えていない。CI の全体検証も merge 前に確認する。

```sh
  "$TINYEXPRESSION_DIR/benchmarks/fixtures/complex.tiny" \
  "$TINYEXPRESSION_DIR/benchmarks/fixtures/complex-x64.tiny"
```
