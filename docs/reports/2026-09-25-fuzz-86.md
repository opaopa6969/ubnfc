# 意味値の領域の中の text だけの規則（#86）

直接 capture の帯（`DIRECT_CAPTURE_SEED_BASE` = 1,000,000）の seed **1000189** が `diff:/ast/fields/tail/*` を出した。
#78（D-078）と signature は同じだが原因は別で、issue の見立て（`L1?` の不在を Rust の `Values{wrap}` fallback が字句にする）とも
違った。値の `"i"` は**省略された `L1?` から来たのではなく**、その隣の `imp.Piece+`（text だけの規則）から来ていた。
Rust が逸脱で、Rust だけを直した。新しい D 行は足していない（D-032 で決まっている）。

## 1. 再現と縮小

`ubnfc-fuzz --start-seed 1000189 --seeds 1 --inputs 12 --shrink-builds 40`（修正前の生成器、`UBNFC_RUST_GENERATOR`）の縮小結果
（`crates/ubnfc-fuzz/findings/diff-ast-fields-tail-bf11b609-seed1000189/`）:

```ubnf
  @enum L1 ::= 'gamma';
  M0 ::= L1? @v3 imp.Piece+ % '\n' @v4 | 'c' @v5 '😀' @v6;      // imported: Piece ::= 'i' | 'j';
  @root @mapping(Top, params=[head, tail, v7, direct])
  Root ::= Op1 @head ( ',' @tail ( M0{2,} % '(' ')' @v7 | M0 L0 ) )* @tail Direct @direct;
```

入力 `c😀,c😀i)2:1''` で `tail`: java=`[",", "c😀"]`、rust=`[",", "c😀", "i"]`。

さらに手で縮めた形（`crates/ubnfc-fuzz/tests/text_rule_value_region.rs`、`P ::= 'i' | 'j'` は写像なし）:

| 文法（`Root ::= '[' … @x ']'`） | 入力 | Java | Rust（修正前） |
|---|---|---|---|
| `( L? P+ \| 'c' 'd' )+ @x` | `[i]` / `[cdi]` / `[cdgammai]` | `[]` / `["cd"]` / `["cd","GAMMA"]` | `["i"]` / `["cd","i"]` / `["cd","GAMMA","i"]` |
| `( L? P ) @x` | `[i]` / `[gammai]` | `null` / `"GAMMA"` | `mapped value type mismatch`（両方） |
| `( L P ) @x` | `[gammaj]` | `"GAMMA"` | `mapped value type mismatch` |
| `( P Leaf ) @x` | `[ix]` | `Leaf` | `mapped value type mismatch` |
| `( Leaf? '-' P ) @x` | `[-i]` / `[x-i]` | `null` / `Leaf` | `mapped value type mismatch` |
| `( L? 'i' ) @x`（literal） | `[i]` | `null` | `null`（一致） |

最後の行が示すとおり、**省略の不在そのものは両 backend とも値を作らない**。差が出るのは連接の中に
**text だけの写像なし規則への参照**があるときで、`L` が有っても（`[gammai]`）差が出る。

## 2. 契約の読み

- 省略された optional は値を作らない（D-032: `X?` は Optional、不在は 0 個）。issue の問いの「採用されて空に一致した」
  （D-078: text 候補は空でも `""`）と「採用されなかった」の区別はこの事例では効いていない。`L1?` は不在で、両 backend とも値なし。
- 値を持つ領域（D-032 の意味形が Some）の中の text は**区切り**で値にならない。text だけの規則への参照も text である
  （意味形は None。Rust の `semantic_shape`、Java の `SemanticShape` とも同じ判定）。
- text だけの規則が値になるのは、それが capture の直下にあるとき（`P @x` → `"i"`）、反復の capture の要素（`P* @x` → `["i","j"]`）、
  mixed な選択の text 候補（D-078）のように、**値の領域の外**で字句そのものが値として問われるときだけ。
- Java はこの読みどおり: 写像なし規則の `values` は null（plain text）で、`combine` は null の項目を値の列に数えない。
  旧実装（`MapperRuleEmitter.semanticValues`: 子の値が空なら何も返さない）とも一致する。

→ **Rust が逸脱**。D-032 / D-078 で決まっているので D 行は足さない。

## 3. 原因

Rust の mapping は、recipe を持たない（写像なしの）規則の `Event::Rule` について「子が値を作らず、値の群も持たなければ
一致範囲の字句を 1 つ値にする」（`mapping.rs` の `rule_mapping`）。これは値の領域の外（capture の直下）では正しいが、
`Values{text:false}` の子として組み立てられるときも同じ字句を足していた。`M0` の第 1 候補 `L1? imp.Piece+` は
`L1?` が `Repeat{max:1}` のため意味形 List（`wrap:false`）で、issue の見立てにあった `wrap` の fallback は発火していない。

## 4. 修正（Rust のみ）

- 生成 runtime の `Session` に `value_region`（組み立て中の `Values{text:false}` の入れ子の深さ）を足した。
  `build_values_inner` の `Values` 腕は `text:false` のときだけ深さを 1 上げて子を組み立てる。
- 意味形が None で写像なしの規則（`text_only_rule`）の mapping 腕は、`value_region > 0` なら値を作らない。
- 写像される規則（recipe が Skip / Transparent / Text 以外、`opens_value_scope`）の本体に入るときは深さを 0 に戻す
  （その規則の field は新しい値の文脈。`Leaf ::= P @v` の `v` は従来どおり字句）。
- D-078 の text 候補（`Values{text:true}`）は深さを上げないが、その領域は字句 1 つで置き換わるので観測は同じ。
- Java は変えていない。
- 生成物（P4 Rust / self-host）を再生成した。変わったのは `runtime.rs` だけ（P4: text 規則 18 腕、scope を開く規則 90 腕、
  self-host: 4 腕 / 49 腕）。canonical AST golden は変わっていない。

## 5. 回帰試験

- `crates/ubnfc-fuzz/tests/text_rule_value_region.rs`（新規）: 両 backend を突き合わせたうえで値も固定する。issue の形（list 形 /
  scalar 形の選択）、連接の中の text 規則（optional enum / enum / node の前 / 区切りの後）、値の領域の外の text 規則
  （capture 直下 `"i"`、text だけの連接 `"ij"`、反復の capture `["i","j"]`）。修正前の Rust では issue の形から落ちる。
- `tests/campaign.rs` の g に seed 1000189 を加えた（固定 seed は 6 本）。
- 所見 `diff-ast-fields-tail-bf11b609-seed1000189` を `crates/ubnfc-fuzz/findings/` に置いた。

## 6. 掃き出し

条件は各帯 201 seed × 12 入力、`--jobs 4 --shrink-builds 0`。修正前（B = `origin/master` 59744cf の生成器）と修正後（F）を、
同じ fuzz バイナリで `UBNFC_RUST_GENERATOR` だけ差し替えて比べた（Java 側は同一）。fuzz は signature ごとに最初の seed だけを記録する。

| 帯 | 比較 / 全受理（B = F） | 消えた signature（B の seed） | 代表 seed の変化 | 増えた signature |
|---|---|---|---|---|
| 標準 v1（1–） | 2412 / 646 | なし | なし | なし |
| 標準 v2（100001–） | 2412 / 467 | なし | `diff:/ast`・`diff:/mappingError/present`・`diff:/value` の代表が 100038 → 100047 | なし |
| 直接 capture v1（1000000–） | 2412 / 513 | `diff:/ast/fields/tail/*`（1000189） | なし | なし |
| 直接 capture v2（1100000–） | 2412 / 246 | なし | なし | なし |

- 標準 v2 の seed 100038 は個別に再実行（`--shrink-builds 20`）し、B の `diff:/ast`・`mappingError/present`・`value` が F で消えることを確かめた
  （`[ [ L0 ]* Node* T0 ] @v5` の中の写像なし規則 `L0` が Rust で余分な字句になり `mapped value type mismatch` になっていた。同じ原因）。
  残るのは `diff:/captures`（A-7、既知）だけ。3 つの signature は別原因で 100047 に残る。
- discard・driver error はどの帯も 0。

## 7. 残り（別 issue）

調査の途中で、同じ「写像なし text 規則の字句」の経路にある別の差を見つけた。`( P P ) @x Leaf @x` で入力 `[ijx]` に対し
java=`["ij", Leaf]`、rust=`["i", "j", Leaf]`。値の領域の**外**（node 変換の field の capture 直下）で、text だけの連接が 1 つの値に
ならない（D-032 では一致範囲全体で 1 値）。この PR の変更（値の領域の中だけ）とは独立で修正前から出るので、issue #89 に切り出した。
