# text だけの規則が絡む 3 つの capture 形を generator に足す（#93）

issue #93。#89（`( P P ) @x Leaf @x`）は手で縮めた文法でしか固定できておらず、4 帯 × 201 seed の掃き出しに
1 つも現れなかった。同様に #86・D-078 も、固定 seed campaign では偶然当たった 1 seed（`DIRECT_CAPTURE_SEED_BASE + 2` /
`+ 189`）でしか押さえられておらず、generator がこれらの形を確実に作る仕組みは無かった。この PR は直接 capture の帯
（#75）と同じ方式で新しい seed 帯を足し、3 つの形をどの seed でも必ず生成するようにした。

## 1. 新帯 `TEXT_GROUP_SEED_BASE`

`crates/ubnfc-fuzz/src/gen.rs` に `TEXT_GROUP_SEED_BASE = 2_000_000` を追加した。直接 capture の帯と同じ設計:

- 乱数を 1 つも追加で引かない。`text_group = seed >= TEXT_GROUP_SEED_BASE` の分岐は、根の直前に決め打ちの規則
  `TextGroup` を足すだけ。既存の帯（v1 `0..V2_SEED_BASE`、v2 `V2_SEED_BASE..DIRECT_CAPTURE_SEED_BASE`、
  直接 capture v1/v2）の生成物は 1 バイトも変わらない。
- `direct`（直接 capture）の帯とは排他: `direct = (DIRECT_CAPTURE_SEED_BASE..TEXT_GROUP_SEED_BASE).contains(&seed)`
  に変更し、`TEXT_GROUP_SEED_BASE` 以降が `direct` を誤って true にしないようにした。
- 帯の中の版分けも同じ方式（`TEXT_GROUP_SEED_BASE + n` は v1、`+ V2_SEED_BASE + n` は v2）。トークン `TG`
  （identifier）の綴りも v2 の中立語彙 / extern に対応（`v2_spelling` を再利用）。

`TextGroup` 規則（`@mapping(TextGroup, params=[ga, gao, gas, gb, gc, gd1, gd2])`）は 3 つの形を 1 本の規則にまとめて
必ず含む:

```
TgP ::= 'p' | 'q';                       // 写像なし・text だけの規則
@enum TgL ::= 'gamma' | 'delta';
@mapping(TgLeaf, params=[v]) TgLeaf ::= TG @v;

TextGroup ::=
  '{' ( TgP TgP ) @ga  TgLeaf @ga  '}'                      // (a) 89: plain
  '[' ( TgP TgP )? @gao TgLeaf @gao ']'                     // (a) 89: Optional variant
  '<' ( TgP TgP )* @gas TgLeaf @gas '>'                     // (a) 89: Repeat variant
  '(' ( TgL? TgP+ | 'c' 'd' )+ @gb ')'                      // (b) 86
  '|' ( ',' @gc ( TgLeaf+ @gd1 | '=' @gd2 )? )* @gc '|'     // (c) D-078
;
```

- (a) issue #89: 写像なし text 規則だけの group（`TgP TgP`）を、node 型の field（`TgLeaf`）と同じ名前で capture する。
  plain / `?`（`gao`）/ `*`（`gas`）の 3 variant を別 field で並べた。
- (b) issue #86: 意味値の領域（`TgL?` が値を持ちうる）の中の text だけの規則の反復（`TgP+`）は区切りで、
  値は enum の分しか増えない。text だけの候補（`'c' 'd'`）は全体で 1 つの字句。
- (c) issue #78 / D-078: 意味値を持つ選択（node 候補 `TgLeaf+` / text だけの候補 `'='`）が省略可能（`?`）なとき、
  採用された text 候補は一致範囲の字句 1 つとして外側の capture（`gc`）へ渡る。区切り `,` も同じ名前 `gc`
  （`mixed_choice_text_value.rs` の `MixedTail` と同じ形）。

根は `@mapping(Top, params=[..., tg])` を必ず持ち、`TextGroup @tg` を field に載せる（`direct` と同じ理由:
根が transparent だと別の差になる）。

## 2. 既存 seed が不変であることの固定

`gen.rs` に `existing_bands_are_byte_identical_after_adding_the_text_group_band` を追加した。既存 4 帯
（v1・v2・直接 capture v1・v2）の最初の 3 seed の `render()` 出力のハッシュ（`DefaultHasher`）を、この PR を書く前の
master で採取した値に固定した。今回の変更後も全て一致することを確認済み。

`text_group_captures_appear_only_in_their_own_band_for_both_versions` は、既存 4 帯（seed 0〜199 の各帯）に
`TextGroup` / `textGroup` feature が 1 件も現れないこと、新帯の seed 20 本ずつ（v1 / v2）が必ず 3 つの形すべてを
含むことを固定する。

## 3. 修正前コミットで赤、現 master で緑であることの確認

`UBNFC_RUST_GENERATOR` で `ubnfc-rust` バイナリだけを差し替え、同じ新帯の文法・同じ Java driver で比較した
（`crates/ubnfc-harness/src/runner/rust.rs` の env var）。3 つの修正前コミットを detached worktree で checkout し
`cargo build --offline --bin ubnfc-rust` した:

| コミット | 内容 | 状態 |
|---|---|---|
| `7dbcdec`（#89 修正前 = #90 マージ直後） | #86 は直っているが #89 は未修正 | pre-89 |
| `4c1c543`（#90 = #86 修正 マージ前） | #86 も #89 も未修正 | pre-86 |
| `cefdbd7`（#88 = D-078 修正 マージ前） | D-078 も #86 も #89 も未修正 | pre-78 |

seed `TEXT_GROUP_SEED_BASE + 2`（= 2000002、v1 帯）で 48 入力を比較した結果（`diff:/ast/fields/tg/fields/*`）:

| コミット | 出た signature |
|---|---|
| 現 master（post-fix） | **0 件**（v1 帯 3 seed・v2 帯 3 seed、全 6 seed） |
| `7dbcdec`（pre-89） | `fields/ga/*`, `fields/gao/*`, `fields/gas/*`（(a) だけ。#86 は直っているので (b)(c) は出ない） |
| `4c1c543`（pre-86） | `fields/ga/*`, `fields/gao/*`, `fields/gas/*`, `fields/gb/*`（(a)(b)。D-078 は直っているので (c) は出ない） |
| `cefdbd7`（pre-78） | `fields/ga/*`, `fields/gao/*`, `fields/gas/*`, `fields/gb/*`, `fields/gc/*`（(a)(b)(c) 全部） |

3 つの修正がそれぞれ対応する signature を消していることが、1 本の seed で層になって確認できた。
（(c) の `fields/gc/*` は 12 入力では踏めず、48 入力にして初めて踏めた。固定 campaign の入力数もこれに合わせて
48 にした。）他の seed（`+1`, `+3`, v2 帯の `+1`〜`+3`）は今回の 12〜48 入力の範囲では踏まなかった
（入力導出が乱択のため。`+2` を固定 campaign の代表 seed にした理由）。

## 4. 固定 seed campaign への登録

`crates/ubnfc-fuzz/tests/campaign.rs` に `h_text_group_captures_agree_across_backends` を追加した。
v1 帯 3 seed（`base+1, base+2, base+3`）・v2 帯 3 seed（`v2+1, v2+2, v2+3`）を 48 入力で比較し、
未登録の signature が 0 件・全入力受理が 1 件以上あることを確認する。現 master で緑。

| D-028 `mappingError`/`value` の有無 | 根が空一致したときの扱い | △ `@mapping` を持つ固定 seed は多い（a/g/h 等）が、「根が空一致」という**具体的な入力**を狙って固定した seed は無い（一般カバレッジのみ） |

| D-032 量指定子つき capture の cardinality | site の量指定子で出現を数え、内側は意味値だけ増やす | ✅✅ g(base+189: #86 の元 seed)。**h の新帯そのものが D-032 の境界を専門に踏む**（`ga`/`gao`/`gas`: なし/`?`/`*`、`gb`: 選択+反復、`gc`: 反復の中の mixed choice） |
| D-035 出現表・value span は opt-in | `ParseOptions.occurrences`/`value_spans` | ❌ `campaign::Config` はこのオプションを露出しない（grammar 形状ではなく呼び出しオプションの契約なので対象外）。別の専用テストが担当 |
| D-068 AST 経路の capture 包み省略（Java 内部最適化） | 実行時分岐の最適化、観測は不変 | ❌ 生成文法に依らない Java 内部の等価性の話で、`AstBypassEquivalenceTest` 側が正本。fuzz campaign の対象外 |
| D-069 回復の観測は Java を正本にする | 回復診断候補・`captureOccurrences` | ✅✅ f(v2+276) がこの決定そのものの回帰 seed |
| D-074 直接 capture は原文の文字列 | 数値 token の特例廃止 | ✅✅ g(全 6 seed) が `capture:directToken`（`DN`/`DI`/`DS`/`DG` の直接 capture）を必ず持つ |

❌ このテスト対象では踏めない（grammar 形状ではなくオプション/内部実装の契約なので、別の専用テストが正本）。
